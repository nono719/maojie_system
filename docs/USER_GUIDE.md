## 〇、五分钟启动顺序

| 步骤 | 操作 | 说明 |
|------|------|------|
| 1 | `docker compose up -d` | 起 MySQL (13306) + Redis (16379)，首次会自动跑 `sql/init.sql` 建表 |
| 2 | 启动 FISCO BCOS 节点（端口 18545） | 给后端提供链上 JSON-RPC |
| 3 | 部署合约 `mvn exec:java -Dexec.mainClass=com.breathchain.tool.ContractDeployer ...` | 得到 BreathToken 和 TrainingRecord 地址 |
| 4 | 把合约地址 + 服务账户私钥写入 `backend/src/main/resources/application.yml` | 后端用 |
| 5 | `cd backend && mvn spring-boot:run` | 后端起在 18080 |
| 6 | `cd frontend && npm install && npm run dev` | 前端起在 15173 |
| 7 | 浏览器打开 http://localhost:15173 | 进入登录页 |

**默认账号**（密码统一 `admin123`）：

- `admin` — 管理员
- `doctor01` — 医生（已认证）
- `patient01` — 患者（已绑定 doctor01）

## 一、登录与多角色并行

**入口**：http://localhost:15173/login

### 多角色同时登录

浏览器开多个 **标签页**（不是窗口），每个 tab 走 `sessionStorage` 独立存 token，可以同时登 admin / doctor / patient 互不覆盖。这是为了演示三角色互动专门做的隔离。

### 登录页操作

1. 输入用户名 + 密码
2. 点「登录」按钮
3. 系统按角色跳转：
   - ADMIN → `/admin/dashboard`
   - DOCTOR → `/doctor/dashboard`
   - USER → `/patient/home`

右下角「立即注册」跳到注册页。

## 二、注册流程

**入口**：http://localhost:15173/register

### 2.1 患者注册

1. 顶部 Radio 选「👤 患者」
2. （可选）右上角点 **⚡ 填充测试数据** —— 自动生成随机用户名/姓名/手机号 + 默认密码 `admin123`
3. 填写：用户名（3-50 字符）/ 密码 / 真实姓名 / 手机号
4. **「主治医生」下拉框**：选择已认证的医生（显示 "姓名 · 职称 · 医院 · 科室"）
   - 此项可选；不选医生也能注册，后续可由管理员或医生申请绑定
5. 点「注 册」→ 自动登录跳到患者首页

### 2.2 医生注册

1. 顶部 Radio 切到「🩺 医生」
2. （可选）点 **⚡ 填充测试数据** —— 同时填好执业证号/医院/科室/职称
3. 必填：用户名 / 密码 / 真实姓名 / 手机号 / **执业医师证书号** / 医院 / 科室 / 职称
4. 页面会出现蓝色提示条：「医生账户须通过管理员审核后方可使用全部功能」
5. 点「提交审核申请」→ 弹窗「注册成功，等待审核」→ 返回登录页
6. **此时也可以登录**，但功能受限（见 3.1）

### 2.3 重名错误

如果用户名已存在，系统弹红色提示「**用户名已被占用，请换一个**」，不会再暴露 SQL 错误。

## 三、医生端

`/doctor/*`

### 3.1 未通过认证时的限制状态

未通过认证的医生登录后**可以浏览页面但不能操作**：

- 顶部黄色横幅：「您的医生资质正在等待管理员审核」
- 侧边栏「任务管理 / 患者管理 / 患者分配申请」菜单变灰、不可点击
- 即使绕过前端直接调后端写接口（创建任务、申请等）也会被拦截返回 `1005 医生账户待管理员审核通过后才能登录`

### 3.2 数据概览 `/doctor/dashboard`

显示四个统计卡：

- 🧑‍⚕️ **我的患者**：绑定到我的患者总数
- 🔥 **今日训练**：我名下患者今天完成的训练次数总和
- 📝 **活跃任务**：我创建的状态为 PUBLISHED 的任务数
- 🪙 **累计发奖**：我的患者群累计获得的 BREATH 总量

下方 ECharts 趋势图：最近 7 天我的患者群每天训练次数 + 平均完成率。

### 3.3 任务管理 `/doctor/tasks`

**新建任务**（右上角「➕ 新建任务」按钮）：

1. 填任务名称（必填）+ 奖励数量（默认 10 BREATH）
2. 填任务描述（建议简短说明用途）
3. **「呼吸阶段配置」** 用 `BreathPhaseEditor` 组件操作：
   - 顶部彩色横条按时长比例展开 吸（青）→ 屏（绿）→ 呼（蓝）→ 保（紫）
   - 实时显示「单次循环 X 秒」
   - 四个阶段独立卡片，调每个阶段的秒数（吸/呼最少 1 秒，屏/保允许 0）
4. **「训练强度」**：单次时长 + 每日次数
   - 下方蓝色提示：「本次训练约可完成 N 个完整呼吸循环」
5. 点「创建」→ 任务进入 **DRAFT（草稿）** 状态

**发布任务**：表格中草稿状态的任务点「发布」→ 状态变 **PUBLISHED**，患者可见。

**分配给患者**：已发布的任务点「分配给患者」→ Modal 多选患者 → 确认 → 患者端立即收到任务。

### 3.4 患者管理 `/doctor/patients`

- 列表显示所有绑定到我的患者（用户名、姓名、手机号、钱包地址）
- 点「查看详情」打开右侧抽屉（Drawer）：
  - 患者基本信息（用户名/姓名/手机/邮箱/钱包地址）
  - 最近活跃时间
  - 三个统计卡：累计训练次数 / 平均完成率 / 累计奖励
  - 最近 10 次训练记录表格（带「验证」按钮一键查链上一致性）

### 3.5 患者分配申请 `/doctor/requests`

医生**没有权限直接修改患者的绑定关系**，必须走申请：

1. 点「➕ 新申请」
2. 输入患者用户名（精确匹配）+ 申请理由
3. 提交 → 状态 PENDING
4. 等待管理员审批
5. 通过后患者的 `doctor_id` 自动更新为我，立即出现在「患者管理」列表

**防呆校验**：

- 患者已绑定到我 → 立即提示「该患者已经是您的患者」
- 同一医生针对同一患者已有未处理申请 → 拒绝重复

## 四、患者端

`/patient/*`

### 4.1 首页 `/patient/home`

**四个统计卡**：

- 🔥 **今日训练** 次数
- 📊 **累计训练** 次数
- 🪙 **代币余额** —— 从链上 `balanceOf(walletAddress)` 实时读
- ⭐ **连续打卡** 天数（最近连续每天至少 1 次训练）

ECharts 7 天训练 + 完成率趋势。

下方「今日待完成训练」卡片列表 —— 每个任务一张渐变卡片，显示吸/屏/呼/保配置 + 单次时长 + 奖励数量，右侧「开始训练」按钮。

### 4.2 我的训练 `/patient/tasks`

显示所有医生分配给我的任务（不只今天），点「开始训练」进入训练页。

### 4.3 训练页 `/patient/training/:taskId`

**关键交互**：

1. 页面顶部显示任务名 + 描述
2. 中央一个大圆球（CSS scale 动画 + 渐变色）
3. 下方三个实时指标：剩余时间 / 已呼吸次数 / 完成度 %
4. 点「开始训练」：
   - 圆球按吸气（变大、青色）→ 屏息（保持大、绿色）→ 呼气（缩小、蓝色）→ 保持（保持小、紫色）循环
   - 阶段名 + 倒计时秒数显示在圆中央
5. 训练过程中任何时刻可点「提前结束」→ 系统按 已用时间 / 总时长 计算完成率
6. 时长到自动结束
7. 结束后弹出 **训练完成 Modal**（重要！）：

#### 训练完成 Modal 内容

- **顶部橙色横幅**：「+X.X BREATH 本次奖励到账 🎉」
  - 如果完成率不足 5% → 灰色「未发奖」横幅
- **奖励明细分块**：
  - 任务基础奖励：10 BREATH
  - 连续打卡：7 天
  - 加成原因（逐条列出）：
    ```
    ✓ 完成率 88.0% (优秀 80-89%) × 0.9
    ✓ 评分 ≥ 90 高质量加成 × 1.2
    ✓ 连续打卡 7 天「钢铁意志」× 1.5
    ```
- **上链信息分块**：
  - 记录 ID #N
  - 上链状态 Tag
  - 数据哈希（截断显示，可在历史页看完整）
  - 区块链交易哈希

关闭 Modal 或点「返回首页」回到 `/patient/home`，余额已自动刷新。

### 4.4 训练历史 `/patient/history`

表格：时间 / 任务 ID / 时长 / 呼吸次数 / 完成率 / 评分 / 上链状态 / 交易哈希预览

### 4.5 奖励记录 `/patient/rewards`

表格：时间 / 任务 ID / 奖励数量 / 状态（SUCCESS / PENDING / FAILED）/ 链上 txHash

### 4.6 患者钱包地址配置（重要！）

**患者本人没有"绑定钱包"的入口** —— 故意这样设计，避免普通用户误改导致奖励发到错误地址。流程是：

**方式 A：注册时自动**

- 当前注册流程**不要求**患者自行准备钱包
- 系统不会自动生成钱包
- 注册成功后 `wallet_address = NULL`

**方式 B：管理员代配（推荐）**

1. 管理员登录 → `/admin/users` 找到该患者
2. 点该行的「详情/编辑」
3. 在「区块链钱包地址」字段粘贴 `0x...`
4. 保存

**方式 C：医生在线下沟通后请管理员配**

- 医生通过站外渠道（微信/电话）拿到患者的钱包地址
- 通知管理员去配

**方式 D：批量配置（SQL）**

```sql
UPDATE sys_user SET wallet_address='0x...' WHERE username='patient01';
```

**为什么是这样设计**：

- 训练完成时如果患者**没有钱包地址**，系统会照常落库 + 上链 + 计算奖励数量，但**跳过实际发币**（`rewardStatus=SKIPPED`），同时返回完整的奖励明细给前端展示
- 这样不影响训练流程，等钱包配上后从下一次开始正常发币

**怎么生成一个新钱包**：

```bash
cd backend
mvn exec:java -Dexec.mainClass=com.breathchain.tool.WalletGenerator -Dexec.args="3"
```

输出 3 个地址 + 私钥（secp256k1 / EVM 兼容）。把任意一个 address 粘到 `wallet_address` 字段，**私钥患者本人保管**。

## 五、管理员端

`/admin/*`

### 5.1 数据概览 `/admin/dashboard`

7 个统计卡 + 7 天双线 ECharts（训练次数 + 发奖数量）：

- 👥 用户总数
- 🩺 医生数
- 🤝 患者数
- 📝 训练任务数
- 📋 训练记录数
- 🪙 累计发奖
- ⛓ 链上区块号

### 5.2 用户管理 `/admin/users`

列表显示所有用户（角色 Tag、状态 Tag）。

**详情/编辑**（每行按钮）：弹窗内可改：

- 真实姓名 / 手机号 / 邮箱
- 角色（受保护：自己是 ADMIN 时不能改自己；任何用户不能升级为 ADMIN）
- **绑定医生**（仅 USER 角色显示此下拉框） —— 这是管理员"直接分配患者给医生"的入口
- 状态（启用/停用，ADMIN 受保护）
- **区块链钱包地址** —— 患者绑定钱包的主要入口

**启用/停用**：行内一键切换，管理员自身受保护。

### 5.3 医生审核 `/admin/doctors`

列出所有有 `doctor_profile` 的医生 + 资质信息 + 认证状态（待审核 / 已认证 / 已驳回）。

- **通过认证**：点「通过认证」→ `certified=1` + `status=1`（同步启用账户）→ 该医生下次登录顶部黄条消失、菜单全亮
- **驳回**：点「驳回」二次确认 → `certified=-1` + `status=0`（账户停用）→ 被驳回的医生无法再登录

### 5.4 患者分配 `/admin/requests`

医生发起的患者绑定申请汇总：

- Tab 切换：待审批 / 已通过 / 已驳回 / 全部
- 列表显示：医生 / 患者 / 申请理由 / 当前主治医生 / 状态 / 提交时间
- 「通过」按钮 → 二次确认 → patient 的 `doctor_id` 自动更新为申请医生
- 「驳回」按钮 → 状态变 REJECTED

**两种分配患者的方式对比**：

| 方式 | 入口 | 流程 |
|------|------|------|
| 医生申请 → 管理员审批 | 医生端 `/doctor/requests` | 医生主动发起 |
| 管理员直接分配 | 管理员 `/admin/users` 编辑 | 无需医生发起，管理员直接改 doctorId |

### 5.5 训练记录审计 `/admin/records`

**列表**：用户（姓名 + @username）/ 任务名 / 完成率 / 评分 / 上链状态 / 数据哈希预览 / 时间

**详情**（每行「详情」按钮，弹右侧 Drawer，三段式）：

1. **用户 & 任务**
   - 用户：ID / 用户名 / 真实姓名 / 手机号
   - 任务：ID / 名称 / 描述 / 吸屏呼保配置 / 奖励数量

2. **训练数据**
   - 实际时长（秒）/ 呼吸次数 / 完成率 % / 评分 / 平均心率 / 完成时间

3. **链上信息**
   - 上链状态 Tag（SUCCESS / FAILED / PENDING）
   - **完整 Keccak-256 数据哈希**（带「复制」按钮）
   - **完整区块链交易哈希**（带「复制」按钮）
   - 顶部自动调用合约 `verifyRecord(recordId, dataHash)`，实时显示绿色 Tag「✅ 链上一致」或红色「❌ 哈希不匹配」 —— 这是**论文最关键的可信存证功能**

列表行的「链上校验」按钮 = 不开 Drawer 也能快速校验。

### 5.6 区块链状态 `/admin/chain`

只读展示：

- ChainID（20200）
- 当前区块号（实时调 `eth_blockNumber`）
- BreathToken 合约地址
- TrainingRecord 合约地址
- 后端服务账户地址（这个账户必须事先调 `setAwarder` / `setSubmitter` 加入合约白名单）

## 六、奖励机制

### 完成率阶梯

| 完成率 | 系数 | 称号 |
|--------|------|------|
| < 5% | 0 | 不发奖 |
| 5–29% | × 0.2 | 初步尝试 |
| 30–59% | × 0.5 | 已有进展 |
| 60–79% | × 0.7 | 良好 |
| 80–89% | × 0.9 | 优秀 |
| ≥ 90% | × 1.0 | 完美 |

### 附加加成（叠乘）

| 条件 | 系数 | 称号 |
|------|------|------|
| 评分 ≥ 90 | × 1.2 | 高质量训练 |
| 连续打卡 ≥ 3 天 | × 1.3 | 毅力之星 |
| 连续打卡 ≥ 7 天 | × 1.5 | 钢铁意志（覆盖前者） |

### 安全限制

- 单次最高 `base × 2`
- 链上合约层面：**同人同任务同日只能领一次**（防刷）
- 完成 Modal 会逐条显示加成原因供患者查看

**示例计算**：任务 base=10，完成率 88% + 评分 92 + 7 天连续打卡

```
10 × 0.9 × 1.2 × 1.5 = 16.2 BREATH
```

## 七、区块链相关功能

### 7.1 训练完成自动上链

1. 患者完成训练 → 后端先落库 `training_record`（status=PENDING）
2. 后端按 `userId|taskId|duration|completion|score|timestamp` 拼接计算 **Keccak-256 哈希**
3. 调用 `TrainingRecord.addRecord(recordId, ..., dataHash)` 上链
4. 等待区块链回执 → 更新数据库 `block_tx_id` + `chain_status=SUCCESS`

### 7.2 自动发币（满足条件时）

1. 完成率 ≥ 5% 触发 `BreathToken.awardUser(toAddress, taskId, amount)`
2. 同人同任务同日多次只发首次 —— 由合约 `dailyClaimed` 状态保证
3. 患者钱包余额随 mint 增加

### 7.3 链上数据校验

1. 管理员在 `/admin/records` 选某条记录点「链上校验」
2. 系统调 `TrainingRecord.verifyRecord(recordId, expectedHash)` 视图函数
3. 返回 true → 数据从未被篡改；false → 数据库被改过

医生端在「患者管理 → 查看详情 → 最近 10 条记录」也能逐条校验。

### 7.4 查链上余额

后端接口：

```
GET /api/chain/balance/0xADDRESS
```

返回该地址的实时 BREATH 余额。前端患者首页的「代币余额」卡就是这个数据。

### 7.5 怎么知道哪些钱包是测试用的

最简单：用 `WalletGenerator` 工具生成。

```bash
cd backend
mvn exec:java -Dexec.mainClass=com.breathchain.tool.WalletGenerator -Dexec.args="5"
```

每个钱包输出地址 + 私钥。**仅供测试**，地址 = secp256k1 公钥的 Keccak-256 后 20 字节，与以太坊地址格式完全兼容。

## 八、常见操作场景

### 场景 1：新医生入职完整流程

| 步骤 | 角色 | 操作 |
|------|------|------|
| 1 | 新医生本人 | 注册页选「医生」→ 填资质 → 提交（弹窗"等待审核"） |
| 2 | 新医生 | 立即登录可进入医生端，看到黄色横幅、菜单灰着 |
| 3 | 管理员 | `/admin/doctors` 看到该医生「待审核」状态 |
| 4 | 管理员 | 点「通过认证」 |
| 5 | 新医生 | 退出再重登（或刷新拿新 token），横幅消失，功能全部启用 |
| 6 | 新医生 | 在「任务管理」创建训练任务 |

### 场景 2：新患者完整入驻流程（最完整）

| 步骤 | 角色 | 操作 |
|------|------|------|
| 1 | 新患者本人 | 注册页选「患者」→ 下拉选医生 → 提交 → 自动登录 |
| 2 | 患者 | 此时 `wallet_address` 为空，训练能完成但不发币 |
| 3 | 管理员 | 用 `WalletGenerator` 生成一个新钱包 |
| 4 | 管理员 | `/admin/users` 找到该患者 → 「详情/编辑」→ 粘贴钱包地址 → 保存 |
| 5 | 管理员 | 把私钥通过站外安全渠道交给患者本人保管 |
| 6 | 医生 | 在「任务管理」创建任务 → 「分配给患者」选中该患者 |
| 7 | 患者 | 进首页看到待办任务 → 点「开始训练」 |
| 8 | 患者 | 训练完成 → 弹窗看到奖励到账 + 钱包余额增长 |

### 场景 3：医生想接管一个不在自己名下的患者

| 5 | 医生 | 「患者管理」立即可见该患者 |

### 场景 4：管理员怀疑某条训练数据是假的

| 步骤 | 操作 |
|------|------|
| 1 | `/admin/records` 找到可疑记录 |

## 九、常见问题速查

| 问题 | 解决 |
|------|------|
| 浏览器一直转圈 | `Cmd+Shift+R` 硬刷新；或用无痕窗口 |
| 同时打开两个角色互相覆盖 | 用 sessionStorage 隔离，开**新标签页**（不是新窗口） |
| 训练完成显示「未发奖」 | 完成率 < 5%（防刷），或患者没绑钱包 |
| 医生菜单全灰 | 还在等审核 → admin 去「医生审核」点通过 |
| Dashboard 全是 0 | 后端没起 / 没数据 → 看 admin 概览 |
| 注册「用户名已存在」 | 换个用户名重试 |
| 链上验证显示「❌」 | 数据被人改过；或链没起来（验证返回 null） |
| 钱包余额一直 0 | 患者 `wallet_address` 没设；或后端服务账户没加合约白名单 |

## 十、整体架构速图

```
浏览器（多 tab）
   ↓ HTTP
Vite 15173 (前端)
   ↓ /api 代理
Spring Boot 18080 (后端)
   ↓ JDBC/Redis        ↓ Web3j
MySQL 13306 / Redis 16379    FISCO BCOS 18545
                              ↓
                         BreathToken / TrainingRecord 合约
```

- **链下**：原始训练数据存 MySQL
- **链上**：仅 Keccak-256 哈希 + 代币转账
- **任何人篡改数据库** → 校验时哈希对不上 → 系统识别

这就是论文核心创新「**链下大数据 + 链上哈希存证**」的实现方式。
